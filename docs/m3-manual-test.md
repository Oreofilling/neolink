# M3 手工测试用例（desktop_app）

- 适用版本：`desktop_app_m3d.zip`（neolink main M3d 修复批）
- 日期：2026-11-03（M3d 第四轮：重检可见反馈与超时兜底。
  此前 M3c 第三轮：A1 倒计时醒目化、A2 自检页侧栏可达；
  M3b 第二轮：A1 倒计时、A2 任意相位重检、B/C 时效标注、E5 跟随系统）
- 真机固件边界：F1 固件只实现 `device.info.get` 与 `session.close`；
  `communication.capabilities.get` / `config.set` / `communication.scan` 均回答
  `UNSUPPORTED_OPERATION`。因此 **A/B/C/E 组今天在真机可完整手测；D 组（表单与下发）
  真机不可达**，进不了能力页——能力读取一步即被拒，这是预期行为，不是客户端 bug。
  D 组用例列出供 F2 固件刷入后回归。

## 准备

1. Windows 10/11 + 蓝牙。用 RTL8761B dongle 时驱动必须是 1.6.1015.3018
   （其他版本枚举失败，自检会显示适配器异常）。
2. NE101 上电即进配置模式，广播窗口约 60 秒后自动深睡；重新上电开始新一轮。
   距离放近（<2m），手边随时可重新上电。
3. 解压 zip 后整目录运行 `desktop_app.exe`（`flutter_windows.dll` 须同目录）。
   首次运行 Windows 蓝牙授权/防火墙提示一律允许。
4. 记录方式：每条标 通过 / 不通过；不通过时记现象 + 截图。

## A 环境自检（启动首屏）

**A1 正常自检通过 → 倒计时进入扫描（M3c：倒计时醒目化）**
- 操作：启动 exe，等 1–3 秒。
- 预期：三行通道卡——蓝牙 BLE「可用/正常」；无线网卡（AP）有启用网卡时
  「可用/正常」，无网卡时「受限/未检测到无线网卡…」；CT-Disc「受限/本版本未接入，预留」。
  卡片中部出现**醒目倒计时条**：大号数字秒数（如「5」）+「秒后自动进入扫描」+
  一条随秒数递减收缩的进度条；旁边两个按钮：「停留本页」取消倒计时
  （状态变「已停留本页…」，保留通道明细可慢慢看）、「立即扫描」不等倒计时直接进
  扫描页。也可什么都不点，数完自动进扫描页。

**A2 蓝牙关闭后重新检测（有无线网卡的机器）**
- 操作：系统快速设置关蓝牙 → 自检页点「重新检测」；再从侧栏回「环境自检」页
  （此时已在扫描页）再点一次「重新检测」。
- 预期：蓝牙 BLE 行变「受限」，原因「蓝牙射频已关闭」；无线网卡行仍可用 →
  因「至少一条通道可用」仍进入扫描（已知边界：AP 通道 M5 才接入，
  此时扫描走 BLE，预期 20 秒后空态页「未发现设备」，记录实际现象）。
  扫描中途回自检页（M3c 修复点）：侧栏点「环境自检」即可进入且**可停留**——
  页面周期刷新不再把人拽回扫描页；重新检测只刷新通道状态，不打断扫描、不跳页。
  链路真推进时（如出现候选）仍会自动切页，属预期。
  重检可见反馈（M3d 修复点）：点击「重新检测」（含刚进入页面时的自动复检）后
  状态行立即变「正在检测环境…」，完成后按钮下方出现/刷新
  「上次检测 HH:MM:SS」时间戳——即使通道行值没变，也能确认检测确实跑过。
  若某路探测卡住（如蓝牙射频切换瞬间），10 秒内按超时收敛为「受限/稍后重试」，
  不会永远停在检测中。

**A3 全部通道不可用 → 阻塞在自检页，修复后免重启放行**
- 操作：关蓝牙（且机器无无线网卡/网卡禁用）→「重新检测」→ 重新打开蓝牙 →
  再点「重新检测」。
- 预期：三行全部受限/不可用，顶部「暂无可用通道 — 处理上方受限项后重新检测」，
  停留自检页；修复环境后在同一运行内再「重新检测」即恢复并进入扫描
  （M3b 修复点：无需重启应用）。

## B 扫描设备

**B1 空扫超时进空态页**
- 操作：设备不上电，等 20 秒。
- 预期：进「未发现设备」空态页，提示含「上电后 60 秒内」；侧栏「未发现设备」点亮；
  「重新扫描」可点。

**B2 候选出现与信息完整**
- 操作：空态页点「重新扫描」后给 NE101 上电。
- 预期：数秒内出现候选行：型号 NE101、「标识 AABBCC」（MAC 后 3 字节）、
  信号「-XX dBm」、按钮「连接」；标题「N 台候选」。

**B3 重新扫描刷新**
- 操作：点「重新扫描」。
- 预期：列表清空重扫；设备仍广播则再次出现，信号值有更新。

**B5 结果页是快照不是实时列表（M3b：断电条目标注而非消失）**
- 操作：候选出现后（已停源），给设备断电，盯住该条目 15–20 秒。
- 预期：条目**不会消失**。约 3 秒后出现时龄标注「最后见到 N 秒前」并持续增长；
  超过 12 秒后整行变淡并带「信号消失」徽章，「连接」仍可点
  （点了会走连接失败错误卡，属正常兜底）。
  设计说明：出候选即停止扫描射频（挑选期间射频静默，保证配对可靠性），
  列表是停源瞬间的快照；要看设备是否还活着，点「重新扫描」开新一轮。

**B4 忙设备不可选（可选，需第二客户端）**
- 操作：另一台电脑/手机 BLE 连上设备保持，再扫描。
- 预期：该候选带「忙」徽章，「连接」不可点。没有第二客户端可跳过。

## C 连接与配对（真机核心路径）

**C1 连接步骤依次推进**
- 操作：点「连接」。
- 预期：建立连接页四步依次点亮：系统配对 → 建立 GATT 链路 → 读取设备信息 → 读取配置能力。
  首次连接 Windows **可能**弹配对确认（Just Works，无需输码），也可能不弹直接走完
  （Windows 对 Just Works/已缓存 bond 常静默通过）——**弹或不弹都算通过**，
  以四步是否依次推进为准（M3b 用例修订）。

**C2 能力读取被拒 = 当前预期终点**
- 预期：读取设备信息完成（此步成功）后，读取配置能力一步失败 →
  错误卡「读取能力失败」，诊断串含 `UNSUPPORTED_OPERATION`（operation not implemented）；
  提示「设备仍在配置模式，可立即重试」；按钮「返回设备列表」。
  顶栏徽章回到「未连接」。**这是 F1 固件的预期行为。**

**C3 返回后立即重连（bonding 缓存验证）**
- 操作：C2 后点「返回设备列表」→ 候选保留 → 立刻再点「连接」（60 秒窗口内）。
- 预期：第二轮起不弹配对提示（bond 已缓存，静默复用），同样走到 C2 终点；
  连续 3 轮稳定。「不弹」本身就是 bond 生效的证据（M3b 用例修订）。

**C4 连接中断错误卡**
- 操作：点「连接」后立刻给设备断电（或等深睡）。
- 预期：错误卡「连接未完成」+ 诊断串 + 「返回设备列表」；候选保留。

**C5 收尾不卡死（737e2f0 修复验证）**
- 操作：在 C2/C4 错误卡反复「返回设备列表」→ 再扫/再连，共 ≥3 轮。
- 预期：全程无白屏、无卡死、无未响应；每轮返回后扫描立即可用。

## D 配置表单与下发 —— F2 后回归（固件侧已真机验证，UI 侧待跑）

> F2 固件（`f2c3a4f` + `b394838`）已实现并在 NE101 真机（wifi SKU）上用 bleak BLE 探针
> 验证（25/25 通过，2026-11-04）：能力形态（4 节/wifi scannable）、扫描分页（32+14 条、
> cursor 续页、陈旧 cursor 拒绝）、config.get 密码掩码、多节 config.set 原子写入 NVS
> （跨重启持久）、非法载荷 INVALID_ARGUMENT 全或无拒绝、session.close。
> 本组用例剩余部分是桌面 app 表单交互（D2/D4/D5/D9 及各页 UI 断言），需跑 app 回归
> （与 M3 验收报告 §13.3/§13.4 对应）。

**D1 能力页**：设备信息卡（NE101-XXXXXX/型号/固件/序列号）、「当前网络：从未配置」、
wifi/cellular/mqtt 三行带「可配置」「支持扫描」「N 个字段」徽章；勾选 + 「开始配置」。
**D2 Wi-Fi 表单**：SSID 空 → 「网络名称（SSID） 必填」；密码 7 位 → 长度不足、64 位 → 超出上限、
留空合法（开放网络）；隐藏网络直接手输名称；载荷预览随输入实时更新。
**D3 Wi-Fi 扫描面板**：「扫描网络」出列表（信号/信道），点选回填 SSID；条目多时「加载更多」分页。
**D4 CAT1**：APN 必填；PIN 输 12 → 「SIM 卡 PIN 格式不正确」，1234 通过；认证方式下拉
none/pap/chap/pap_or_chap。
**D5 MQTT**：启用开关 + 服务器地址 + 端口。
**D6 多节同勾**：载荷预览同一请求包含多节。
**D7 下发成功**：结果页「已写入 N 个配置节」+ 生效方式提示（网络重连后生效等）+「完成」回扫描。
**D8 下发被拒**：横幅「下发被拒，已保留所填内容」+ 错误码；「返回编辑」所填内容保留。
**D9 校验失败零发送**：必填为空点「下发配置」→ 字段级红字即时出现，页面不进「下发中…」态。

## E 壳与通用（无需设备）

**E1 主题切换**：右上角「深色/浅色」即时生效；两主题下文字/徽章对比度正常。
**E2 侧栏导航门禁**：流程/配置/下发分组；当前阶段页高亮；未解锁页不可点；
扫描阶段「配置节/下发确认/下发结果」锁定。真机因能力读取被拒，这三页始终锁定——预期。
**E3 顶栏徽章**：启动「未连接」；连接建立（GATT 起）变「已连接」；回到错误卡/列表后「未连接」。
**E4 窗口**：标题「NeoLink」，任务栏图标为 logo。
**E5 语言跟随系统并持久化（M3b 修复点）**
- 默认跟随系统语言：中文系统显示中文；系统切英文后（重新）启动 app 显示英文。
- 右上角手动切换（中文 ⇄ English）即时生效，并写入
  `%APPDATA%\NeoLink\settings.json`；再次启动 app 保持手动选择的语言
  （手动选择优先于系统语言）。
